Auto-connect GitHub & Build Knowledge Repository Pipeline

## Summary
Set up automated GitHub integration for the Hermes Agent environment. Created a public repository `gilliansoso/hermes-knowledge-base` to serve as a persistent knowledge store for skills (SKILL.md files) and post-task experience documents. Built the automation scripts and cron job infrastructure.

## Key Learnings

1. **Token-based GitHub auth** — `gh` CLI requires `read:org` scope even for personal repos; git credential store with a classic PAT (repo + workflow scopes) works for HTTPS push
2. **HTTPS git push with tokens** — Must use `git credential approve` or write to `~/.git-credentials` with `git config --global credential.helper store`; embedding the token directly in the remote URL is no longer supported by GitHub
3. **Cloudflare Quick Tunnels** — Ephemeral tunnels don't survive session restarts; need to restart cloudflared each session to restore the public URL
4. **trycloudflare limitations** — No uptime guarantee, URL changes on every restart, but zero-config and no account needed makes it great for quick sharing

## Skills Used / Created

- `github-auth` — Authenticated gilliansoso with gh CLI + git credential store
- `github-repo-management` — Created repo via GitHub API, managed remotes, pushed

## Decisions Made

- **Public repo** vs private — Public chosen so the knowledge base is accessible without auth for sharing learnings
- **Daily cron sync** vs real-time — Cron avoids token overhead per-skill update; skills don't change minute-to-minute
- **git credential store** over `gh auth` — gh required read:org scope the token didn't have; credential store works with existing PAT

## Pitfalls Encountered

- `gh auth login --with-token` failed with "missing required scope 'read:org'" — had to fall back to git credential store approach
- `git push` with token-embedded URL failed: "Password authentication is not supported for Git operations" — must use credential helper, not inline URL
- Cloudflare Tunnel 502 errors when the origin HTTP server dies — need to kill stale fuser on port and restart both processes
- `background` HTTP server on port 18888 got killed when the previous session ended, causing 502s on the tunnel
